| KI-008 | 02/11/2026 | The first start of a newly built ad hoc agent is refused by macOS (`Launch Constraint Violation (Constraint not matched)`, `OS_REASON_CODESIGNING`). Hand install: launchd started it again ~10 s later and it ran. DeckOut Dev (registered with `SMAppService`): the agent has no Team ID, so its Login Items record pins the exact build, and a new build is refused until launchd's own retry, ~10 s after the refusal, makes a new record (`Requesting repair LWCR update`; "Bundle identifiers from launchd plist ignored because the executable doesn't have a Team ID"). A registration made after that retry lands on the new record and the agent runs; one made before it lands on the old record and is refused again. The app re-registers once per launch, 10 s after the agent stops answering, so it races that retry: on 21/11/2026 it won by 42 ms at 00:11 and lost by 10 ms at 01:22, leaving the window on "not running" with no decks. Try Again re-registers at once, which starts the retry's wait over, so clicking it can't win. Workaround (dev builds): quit DeckOut Dev and open it again, or wait 15 s and click Try Again once. A signed build carries a Team ID, which macOS matches across builds: the signed update from 2.0.0 to 2.1.0 (26/11/2026, a changed agent, the app replaced while its agent ran) started the new agent at the first try, about a second after the app opened (owner, 21/11/2026: no app change for dev builds alone). If a signed update ever hits it, the fix is a recovery that re-registers every 15 s while the agent doesn't answer. `AgentLink.swift` (`armDeadline`), `AgentRegistrar.swift` |
| KI-009 | 19/11/2026 | The N4 gets no power from the dock's USB-C port (the only USB-C port tried) after being unplugged for more than a few seconds: dark, absent from the USB tree. It powers up only if the port is already live (e.g. a phone plugged in first, then the cable swapped). On USB-A (A-to-C cable) it works every time. Most likely the N4's USB-C socket lacks the resistors that tell a USB-C port to switch power on; not confirmed with a meter. Workaround: connect the N4 to USB-A. |

| KI-012 | 20/11/2026 | Undo groups slider steps, photo moves and zooms by a one-second gap, not by gesture. A pause of over a second mid-drag makes two undo steps (⌘Z twice). Two drags of the same control less than a second apart, with no other change between, are one step: ⌘Z goes back past both, ⇧⌘Z brings both back, and the position between them can't be returned to. Accepted (owner, 20/11/2026): rare and cheap to put right by hand; grouping by gesture would touch the undo history, both sliders, the photo's drag, pinch and scroll zoom. `ConfigStore.swift` (`change`, `coalescing`) |
| KI-013 | 20/11/2026 | A swipe in the same instant DeckOut saves an edit can lose either one: the agent and the app share no lock. If the agent saves the new preset first, the app's save puts the deck back on the old preset (swipe again). If the app saves between the agent reading the file and saving it, the agent's save drops the edit: it vanishes from the window, "Picked up a change made outside DeckOut" shows, and ⌘Z can't bring it back (make the edit again). In a still narrower window the window keeps the edit while the file and the deck don't have it; the next edit in DeckOut saves it again and puts the deck back on the old preset. Accepted (owner, 21/11/2026): it takes a swipe and a save within milliseconds of each other; a shared lock file would let a stuck app freeze the deck. `Agent.swift` (`switchToNextPreset`), `ConfigStore.swift` (`save`) |
| KI-014 | 21/11/2026 | A tap that lands in the gap between two N4 strip blocks counts as a swipe: the N4 sends the same report (`0x38`) for it as for most swipes, and nothing in the report tells them apart. With the swipe set to `next_preset`, a mis-aimed tap switches the preset; swiping on brings it back round. A tap on a block sends its own code and is unaffected. Accepted (owner, 21/11/2026): ignoring `0x38` made almost every swipe fail. `DeckModel.swift` (`swipeCodes`) |

| KI-016 | 21/11/2026 | macOS 27 is untested (owner, 21/11/2026: test on 15 and 26, then release). The agent's plist inside a downloaded DeckOut (`Contents/Library/LaunchAgents/io.github.okoker.deckout.agent.plist`) carries the `com.apple.quarantine` flag from the download (seen on macOS 15, which accepts it). macOS 27's launchd refuses quarantined plists (macOS 27 release notes); whether that covers a plist inside an app bundle registered through `SMAppService` is unknown. | KI-018 | 26/11/2026 | A volume knob with a small step can stall, depending on the speaker. | KI-019 | 26/11/2026 | The keyboard-shortcut recorder (Keyboard Shortcut action, "Click to record") has two edge cases. A media key (Play / Pause, Volume) gets no response: the button stays on "Press the shortcut…" with no message, because macOS sends media keys as a different kind of event from the one the recorder listens for. On a non-US keyboard the label and the saved config name the key by where it sits on a US keyboard: on a French keyboard ⌘A shows as ⌘Q and saves as `cmd+q`, though the deck key still sends ⌘A. Accepted for now (owner, 26/11/2026): rare, and the shortcut itself works. `ShortcutRecorder.swift`, `ActionNames.swift` (`shortcutSymbols`) |
