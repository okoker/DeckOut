# MiraBox Stream Dock N4 — How It Works

What the daemon does with the N4 today. Built 19/11/2026 (design: `docs/design/n4_support.md`). The protocol and the
macOS quirks it shares with the N3 are in `device_quirks.md`.

## Device
- USB `0x6602:0x1001`, product string "HOTSPOTEKUSB HID DEMO", firmware `V3.Mbox_N4.02.014`.
- The daemon claims only the vendor interface (usage page `0xFFA0`, usage 1). The deck's second interface, a boot
  keyboard, is left alone.
- **Connect it to a USB-A port** (A-to-C cable). On the dock's USB-C port it got no power after being unplugged (KI-009).

## Layout and images
| Control | Config key | Wire slot | Image |
|---|---|---|---|
| Top row keys, left → right | `key_1`–`key_5` | 11–15 | 112×112 |
| Bottom row keys, left → right | `key_6`–`key_10` | 6–10 | 112×112 |
| Strip blocks, left → right | `"1"`–`"4"` | 1–4 | 176×112 |
| Knobs, left → right | `knob_1`–`knob_4` | — | — |

Every image is a JPEG turned 180° (the panel is mounted upside down). Icons are trimmed of transparent padding and
fitted inside the key with a 4 px margin.

## Input (event code at report byte 9, state at byte 10)
| Control | Codes | Notes |
|---|---|---|
| Keys 1–10 | `0x01`–`0x0A` | state 1 press, 0 release; actions run on press |
| Knob 1 / 2 / 3 / 4 turn | `0xA1`/`0xA0`, `0x51`/`0x50`, `0x91`/`0x90`, `0x71`/`0x70` | clockwise / anticlockwise, one report per click |
| Knob 1 / 2 / 3 / 4 press | `0x37`, `0x35`, `0x33`, `0x36` | the N4 sends no release |
| Strip tap, blocks 1–4 | `0x40`–`0x43` | one report, no release |
| Swipe | `0x39` | no direction; `0x38` (also sent by some swipes) is ignored and logged |

The N3 uses some of the same codes for other controls; each deck is decoded with its own map, so they never cross-fire.

## Drawing
- Start-up: `DIS`, brightness (`LIG`), `STP`, `CLE`. After that a redraw sends every slot's image in place and one
  `STP` — no `CLE`, which blinks the N4 visibly. Slots without an icon get a black image.
- Brightness 0–100: every step is visibly brighter; 0 is dim, not off.
- `CONNECT` keepalive every 5 s, as on the N3.

## Config (`decks.n4` in `~/.config/vsd/config.json`)
- `brightness` (required); `keys` (`action`, optional `icon`); `knobs` (`rotate` with `action` and `step`,
  `press` with `action`); `strip`; `swipe` (`action`); `lock_photo` (a path).
- Strip block: `type` is `internet`, `load`, `volume`, `picture` (shows `icon`) or `empty`, plus an optional tap
  `action`. Internet blocks also take `host` (default `one.one.one.one`), `arrow_ms` (2; 0 or more) and `timeout_s` (3; 0.1–60). Numbers outside those ranges are refused.
- An unknown block type, broken JSON, or a config file that is a symlink, owned by another user or writable by
  others is refused: at start the daemon exits, on reload it keeps the previous config and logs why.
- A v1.0.0 config (no `decks`) still loads, as the N3 section.

## Live strip blocks
Each block redraws only when what it shows changes. Readings stop while the Mac is locked and when no live block
is on a connected deck.
- **Volume** — the default output device's volume and mute, from CoreAudio listeners (no polling). A 270° arc with
  the percentage; muted: grey arc and "MUTE"; no output device: "–".
- **Load** — every 5 s. CPU: user + system share of all CPU ticks since the last reading (first figure 1 s after
  start), green below 50 %, amber to 79 %, red from 80 %. Memory: 100 − `kern.memorystatus_level`, coloured by
  macOS's pressure level (`kern.memorystatus_vm_pressure_level`: normal green, warning amber, critical red).
- **Internet** — every 5 s, one ICMP echo to `host` over an unprivileged datagram socket (no helper process, no
  root), waiting up to `timeout_s`. Shows milliseconds (one decimal below 10). A red ▲ or green ▼ appears when the
  figure moved by at least `arrow_ms` since the last reading. No reply, or a lookup still running past the timeout,
  turns the block red ("NO REPLY"). All internet blocks share one probe, set by the first one.

## Locked Mac
- Lock is read from macOS's lock and unlock notifications and re-checked against the session every 5 s and on every
  key press, tap or swipe.
- While locked: keys, strip taps and swipes do nothing (logged as "ignored while locked"). Knobs run only the
  built-in actions (volume, mute, ZR7, monitor brightness).
- With a `lock_photo`, the N4 shows the photo across all 14 screens. The photo is scaled to fill the deck's face
  (800×464 in key-image pixels, centre-cropped) and each screen gets its own piece, measured on the unit (keys 172
  apart, rows 176 apart, strip 352 below the top row with blocks 208 apart). Without a photo, or if it can't be read,
  the deck keeps its layout.
- Unlock redraws every deck and restarts the live readings.
- Keep the photo in `~/.config/vsd/`: macOS asks before a background program reads Desktop, Documents, Downloads or
  iCloud Drive, and an unsigned daemon loses that permission on every rebuild.

## Running it
- Reload: `kill -HUP <pid>` or `StreamDeckController --post-reload`. Every deck redraws in place.
- `--config <path>` uses another config file. `--show-lock-photo` keeps the lock photo up without locking the Mac
  (for lining up a photo; development only).
- Measured 19/11/2026 (see `PROGRESS.md`): both decks with the live strip 0.135 % of one core, N3 alone 0.015 %;
  memory 19 MB (`footprint`); no child processes.
